### RemoteDeck_PC_v3.1-power-diag
PDCA feature `rcm-power-diag`. 사용자 질문("녹화장비 종료 지연 설정이 생겼는데 몇 분 뒤 강제 종료? 업데이트로 늦으면? BIOS·CMOS에 걸리면 보고")에서 출발. **rcm-api v1.1.0(규격: 호환되는 추가) + RemoteDeck_PC v3.1.0**. (1) 업데이트 종료 대기: 에이전트가 종료 직전 보류 업데이트(레지스트리 RebootRequired/RebootPending)면 `os_updating` → 허브가 240초 강제 종료 대신 LED off를 `updateWaitMs` 3시간까지 대기, 초과 시 `update_timeout`. (2) 부팅 실패 진단: SmartDeck이 짝 PC에 ICMP ping(10초, 1회 up·3회 down, ARP는 캐시 오판으로 배제) → `deck.state.peer`, 허브가 4분 대기 실패 시 `power.diag` `no_power`/`no_os`(BIOS·CMOS 대기 의심)/`no_agent`/`unknown`, 30분 관찰 후 늦은 부팅이면 `lastError` 해제·`late_boot`. (3) `peerCheck`: 에이전트 접속 중 ping 실패 지속 → unreliable(방화벽). (4) **실기에서 발견**: v3.1 deck을 v1.0 허브에 붙이자 `deck.state`가 통째로 거부돼 `pc`까지 사라짐(.193 즉시 롤백) → `welcome.caps:["peer"]`로 허브가 지원할 때만 보고(v1.0.6 허브 실기 거부 0). 실기: .109 ping up/down·no_power, **.193 + 실제 PC(.105) BIOS 정지 → no_os → 부팅 no_agent → late_boot "전원 켠 뒤 2분 25초"**. 현장 HD-CTR PC는 ICMP 차단이 기본이라 ping 허용 `netsh` 규칙 필수(RECORDER.md 8장). 시험 84/84(신규 13), C# e2e 5/5. matchRate 96%, SC 7/8(실PC 업데이트 종료는 이월). 교훈: 다른 허브에 붙은 장비에 확인 없이 OTA → 펌웨어 올리기 전 `/api/hub`로 현재 허브 확인, 선택 키 추가는 처음부터 caps 협상. rcm-api PR #10(`5420871`), commit `51c78d8`, branch `v3.1-power-diag`. 관련 [[RemoteDeck_PC_v3.0]] · [[project_rcm_hub_virtual_test]] · [[feedback_hardware_first]].

### RemoteDeck_PC_v3.0-IC
`RemoteDeck_PC_v3.0` report Carry "IntegrateController hub 컬럼"의 후속(PDCA feature `ic-hub-v3.0`). 재부재와 RCM 허브를 같은 현장에서 함께 쓰지 않는다는 운영 사실에 따라, 컬럼을 늘리지 않고 **재부재 컬럼 자리를 툴바 "표시 컬럼: 재부재 / RCM 허브"로 전환**(기본 재부재, devices.json `FeatureColumn` 저장, 없거나 모르는 값이면 재부재). `RemoteDeckClient.ParseStatus`가 `/api/status` `hub_*` 6필드를 하위호환 파싱(키 없으면 미지원, 타입 불일치 내성). Option C(새 파일 0, 5 files +178), `MainForm.Designer.cs` 미수정·`ColAttendance.Index` 접근으로 WinForms 3중 방어선 유지. 시험은 사용자 devices.json 덮어쓰기가 권한 검사에서 막혀, **빌드된 어셈블리를 리플렉션으로 호출하는 하네스**(실기 2대 + 목 장비 4종 + 저장소 왕복 11/11)와 가상 허브 중지 실기, 사용자 GUI 확인으로 대체. matchRate 98%, SC 7/7. commit `8255570`, branch `v3.0-ic-hub`. 관련 [[RemoteDeck_PC_v3.0]] · [[project_winforms_designer]] · [[feedback_client_version_follows_contract]].
