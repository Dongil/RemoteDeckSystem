## 1. Background

### 1.1 v2.0 한계

| 한계 | 원인 |
|------|------|
| Web UI가 WiFi AP에서만 동작 | AsyncWebServer는 lwIP 필요, Ethernet2는 자체 TCP/IP 스택 |
| WiFi 제한 환경에서 Web UI 사용 불가 | 관공서/학교 등 WiFi AP 차단 |
| WiFi STA 모드 미지원 | WiFi AP(핫스팟)만 지원 |
| 설정 변경 무인증 | 누구나 IP/MQTT 등 변경 가능 |

### 1.2 v2.1 목표

1. **네트워크 모드 통합**: `ethernet` 또는 `wifi` 모드 중 하나로 모든 서비스 제공
2. **ETH.h 재도입**: W5500을 ESP32 lwIP에 통합하여 AsyncWebServer/WebSocket 유선 동작
3. **WiFi STA 모드**: AP 모드 제거, 기존 네트워크에 연결하여 서비스 제공
4. **Basic Auth 인증**: 설정 변경 API에 ID/PW 인증 적용

## 2. Scope

### 2.1 In Scope

#### 2.1.1 네트워크 모드 통합

| Mode | Interface | 서비스 |
|------|-----------|--------|
| **ethernet** | W5500 via ETH.h (lwIP 통합) | Web UI, WebSocket, MQTT, RS485, UDP Discovery, WOL, NTP, OTA |
| **wifi** | ESP32 WiFi STA | Web UI, WebSocket, MQTT, RS485, UDP Discovery, WOL, NTP, OTA |

- AP 모드 완전 제거
- `deviceconfig.json`의 `network.mode` 값으로 모드 결정
- 부팅 시 설정된 모드로만 동작 (자동 감지 없음)

#### 2.1.2 ETH.h 표준 구현

v2.0에서 ETH.h 링크 문제로 Ethernet2로 전환했으나, 이후 테스트에서 **스위치 자체 문제**로 확인됨 (Ethernet2도 동일 증상, 스위치 교체 후 정상 동작). ETH.h 드라이버 문제가 아니므로 v2.1에서는 **ESP32 Arduino 표준 방식**으로 ETH.h를 사용함.

```cpp
// 표준 ETH.h W5500 초기화
ETH.begin(ETH_PHY_W5500, 1, PIN_ETH_CS, PIN_ETH_INT, -1, SPI);

// Static IP는 ETH_CONNECTED 이벤트 후 적용
WiFi.onEvent(onEthEvent);
// ARDUINO_EVENT_ETH_CONNECTED → ETH.config(ip, gw, sn, dns)
// ARDUINO_EVENT_ETH_GOT_IP → 서비스 시작
```

| 항목 | 구현 |
|------|------|
| INT 핀 | GPIO17 (하드웨어 INT 사용, 표준 방식) |
| SPI 속도 | 기본값 (ETH_PHY_SPI_FREQ_MHZ) |
| Static IP | ETH_CONNECTED 이벤트 후 적용 |
| 링크 대기 | 비동기 (이벤트 기반, 블로킹 없음) |
| DHCP/Static | 설정값에 따라 자동 선택 |

#### 2.1.3 인증 (Basic Auth)

| 항목 | 내용 |
|------|------|
| **초기값** | ID: `admin`, PW: `12345` |
| **저장** | deviceconfig.json `auth` 섹션 |
| **적용 범위** | Web UI 설정 변경 API, UDP SET_CONFIG |
| **미적용** | Web UI 상태 조회(홈), UDP DISCOVER/GET_CONFIG, RS485/MQTT 명령 |
| **PW 변경** | Web UI 설정 페이지 + IPSetupTool |

#### 2.1.4 IPSetupTool 업데이트

- UDP SET_CONFIG 시 auth 필드 포함
- 장치 연결 시 ID/PW 입력 필드 추가
- PW 변경 기능 추가

### 2.2 Out of Scope

- WiFi AP 모드 (제거)
- HTTPS/TLS (ESP32 리소스 한계)
- 멀티 사용자 계정
- Ethernet2 (ETH.h로 완전 대체, 제거)

## 3. Architecture Changes (v2.0 → v2.1)

### 3.1 네트워크 아키텍처

```
v2.0:                              v2.1:
┌──────────────────┐               ┌──────────────────┐
│  Ethernet2       │               │  Mode: ethernet  │
│  ├─ MQTT         │               │  ETH.h (lwIP)    │
│  ├─ UDP Discovery│               │  ├─ Web UI :5050 │
│  └─ WOL          │               │  ├─ WebSocket    │
│                  │               │  ├─ MQTT         │
│  WiFi AP         │               │  ├─ UDP Discovery│
│  ├─ Web UI :5050 │               │  ├─ WOL          │
│  ├─ WebSocket    │               │  └─ OTA          │
│  └─ OTA          │               ├──────────────────┤
└──────────────────┘               │  Mode: wifi      │
                                   │  WiFi STA (lwIP) │
 두 스택 혼합                        │  (동일 서비스)     │
 → Web UI 유선 불가                  └──────────────────┘
                                    단일 lwIP 스택
                                    → 모든 서비스 통합
```

### 3.2 인증 플로우

```
Web UI 접속
├─ 상태 조회 (GET /api/status)    → 인증 불필요 (읽기 전용)
├─ 릴레이 제어 (POST /api/relay)  → 인증 불필요 (운영 명령)
└─ 설정 변경 (POST /api/config)   → Basic Auth 필수
   └─ 브라우저가 ID/PW 입력창 표시
      └─ base64(admin:12345) 헤더 검증
         └─ 성공 → 설정 저장
         └─ 실패 → 401 Unauthorized

UDP SET_CONFIG
└─ JSON에 auth:{user,pass} 포함
   └─ 검증 → 성공/실패
```

### 3.3 인증 적용 범위

| Endpoint / Command | 인증 | 이유 |
|---------------------|------|------|
| GET /api/status | 불필요 | 상태 모니터링은 자유 |
| POST /api/relay | 불필요 | 운영 제어 (MQTT/RS485와 동일 수준) |
| GET /api/schedule | 불필요 | 읽기 전용 |
| GET /api/config | 불필요 | 읽기 전용 (PW 마스킹) |
| GET /api/log | 불필요 | 읽기 전용 |
| **POST /api/config** | **필수** | 네트워크/MQTT 설정 변경 |
| **POST /api/schedule** | **필수** | 스케줄 추가/수정 |
| **DELETE /api/schedule** | **필수** | 스케줄 삭제 |
| **POST /api/ota** | **필수** | 펌웨어 업로드 |
| **POST /api/reboot** | **필수** | 기기 재부팅 |
| **POST /api/auth** | **필수** | 패스워드 변경 (현재PW 확인 필요) |
| UDP DISCOVER | 불필요 | 기기 검색 |
| UDP GET_CONFIG | 불필요 | 읽기 전용 |
| **UDP SET_CONFIG** | **필수** | auth 필드 검증 |
| **UDP REBOOT** | **필수** | auth 필드 검증 |

## 4. Configuration Changes

### 4.1 deviceconfig.json 추가 필드

```json
{
  "network": {
    "mode": "ethernet",
    "ethernet": { ... },
    "wifi": {
      "ssid": "OfficeNetwork",
      "password": "wifi_password",
      "dhcp": false,
      "ip": "192.168.10.196",
      "gateway": "192.168.10.1",
      "subnet": "255.255.255.0",
      "dns1": "8.8.8.8"
    }
  },
  "auth": {
    "user": "admin",
    "pass": "12345"
  },
  ...
}
```

**변경점:**
- `network.wifi`: DHCP 외에 고정 IP 설정 추가 (STA 모드용)
- `auth`: 신규 섹션 (user/pass)

## 5. Module Changes

### 5.1 NetManager → 단일 모드 전환

| 변경 | 내용 |
|------|------|
| WiFi AP 제거 | `startWiFiAP()` 삭제 |
| Ethernet2 제거 | `Ethernet2.h` 참조 완전 제거 |
| ETH.h 재도입 | `ETH.begin()` with 폴링 모드 |
| WiFi STA 추가 | `WiFi.begin(ssid, password)` + 고정 IP 지원 |
| 비동기 연결 | ETH/WiFi 모두 이벤트 기반, 블로킹 없음 |

### 5.2 WebServer → Basic Auth 미들웨어

```cpp
// 인증이 필요한 엔드포인트에 적용
bool checkAuth(AsyncWebServerRequest* req) {
    if (!req->authenticate(config.auth.user, config.auth.pass)) {
        req->requestAuthentication();
        return false;
    }
    return true;
}
```

### 5.3 UDPDiscovery → 인증 필드 검증

```json
// SET_CONFIG with auth
{
  "cmd": "SET_CONFIG",
  "device_id": "node_1",
  "auth": {"user": "admin", "pass": "12345"},
  "config": { ... }
}
```

### 5.4 Web UI → 패스워드 변경 UI

설정 페이지에 패스워드 변경 폼 추가:
- 현재 패스워드 입력
- 새 패스워드 입력
- 새 패스워드 확인
- `POST /api/auth` 호출

### 5.5 IPSetupTool → 인증 지원

- 장치 연결 시 ID/PW 입력 필드
- UDP SET_CONFIG/REBOOT에 auth 필드 포함
- 초기값(admin/12345) 자동 입력

## 7. Risk & Mitigation

| Risk | Impact | Mitigation |
|------|--------|------------|
| 특정 스위치 링크 불가 | LOW | v2.0에서 ETH.h 문제로 오인했으나 스위치 자체 결함으로 확인됨. 표준 구현으로 대부분 환경 대응. 스위치 포트 설정(802.1X, MAC 필터) 확인 안내 |
| WiFi STA 연결 실패 | LOW | 재연결 로직 + 상태 LED 표시 |
| Basic Auth 평문 전송 | LOW | 로컬 네트워크 전용 기기. HTTPS는 ESP32 리소스 한계로 제외 |
| 인증 정보 분실 | LOW | GPIO1 공장 초기화로 admin/12345 복원 |
