## Executive Summary

| Perspective | Content |
|-------------|---------|
| **Problem** | 기존 명령 체계(`{"device_id":"node_1","status":[{"type":"ONLINE","sequence":1,"data":1}],"message":"..."}`)가 복잡하고 API 문서 배포 시 개발자가 이해하기 어려움. 또한 IO 상태 변경을 외부 시스템에 알릴 방법이 없음 |
| **Solution** | 명령/상태 payload를 단순 평문 JSON으로 재설계하고, IO 상태 변경 시 설정된 URL로 HTTP GET 호출하는 Web Request 기능 추가 |
| **Function/UX Effect** | 개발자가 API 문서만 보고 즉시 연동 가능, 기 개발된 웹서비스와 코드 수정 없이 연동 |
| **Core Value** | 미배포 시점에 breaking change 부담 없이 API를 직관적으로 개선, 외부 시스템 연동 확장성 확보 |

## 1. Overview

### 1.1 Purpose

1. **API 단순화**: RS485/MQTT에서 사용하는 Command/Status JSON 구조를 직관적 평문으로 재설계하여 API 문서 배포 시 개발자가 추가 설명 없이 바로 이해하고 개발할 수 있도록 함
2. **Web Request**: IO 상태 변경(릴레이, GPIO, PC-LED) 시 사용자가 설정한 URL로 HTTP GET 호출하여 기존 웹서비스와 무수정 연동 지원

### 1.2 Background

- RemoteDeck_PC는 아직 배포된 적 없어 breaking change 부담이 없음
- 기존 RS485 기반 명령 체계(`CommandConfig`, `StatusConfig`)가 type/sequence/data 배열 구조로 가독성이 낮음
- 외부 웹서비스(홈 오토메이션, 모니터링 대시보드 등)와 연동하려면 별도 미들웨어가 필요한 상황

### 1.3 Related Documents

- 기존 구현: `RemoteDeck_PC/src/config/CommandConfig.h`, `StatusConfig.h`, `JsonUtils.cpp`
- 아카이브: `docs/archive/2026-04/v2.1-네트워크통합-인증/`

## 2. Scope

### 2.1 In Scope

- [ ] RS485/MQTT Command payload 재설계 (평문 JSON)
- [ ] RS485/MQTT Status payload 재설계 (평문 JSON)
- [ ] CommandConfig, StatusConfig, JsonUtils 리팩토링

### 2.2 Out of Scope

- MQTT topic 구조 변경 (기존 유지)
- Web UI 홈/제어/스케줄 탭 변경
- POST 방식 Web Request (GET만 지원)
- Web Request 인증 (Basic Auth 등) - 향후 확장

## 4. API 재설계 상세

### 4.1 Command (수신) - Before vs After

**Before (v2.1):**
```json
{"command":"RELAY","sequence":1,"data":1,"message":"null"}
{"command":"PULSE","sequence":2,"data":500,"message":"null"}
{"command":"GETSTATUS","sequence":0,"data":0,"message":"null"}
{"command":"WOL","sequence":0,"data":0,"message":"AA:BB:CC:DD:EE:FF"}
```

**After (v2.2):**
```json
{"cmd":"relay","relay":1,"state":"on"}
{"cmd":"relay","relay":2,"state":"off"}
{"cmd":"pulse","relay":1,"duration":500}
{"cmd":"pulse","relay":2}
{"cmd":"status"}
{"cmd":"wol","mac":"AA:BB:CC:DD:EE:FF"}
{"cmd":"wol"}
{"cmd":"reboot"}
```

### 4.2 Status (발신) - Before vs After

**Before (v2.1):**
```json
{
  "device_id":"node_1",
  "status":[
    {"type":"ONLINE","sequence":1,"data":1}
  ],
  "message":"192.168.1.200"
}
```
```json
{
  "device_id":"node_1",
  "status":[
    {"type":"RELAY","sequence":1,"data":1},
    {"type":"RELAY","sequence":2,"data":0}
  ],
  "message":"null"
}
```

**After (v2.2):**
```json
{
  "id":"node_1",
  "event":"online",
  "ip":"192.168.1.200",
  "name":"새기기",
  "fw":"2.1.0"
}
```
```json
{
  "id":"node_1",
  "event":"relay",
  "relay1":1,
  "relay2":0
}
```
```json
{
  "id":"node_1",
  "event":"pcled",
  "pc_on":true
}
```
```json
{
  "id":"node_1",
  "event":"gpio",
  "gpio1":0,
  "gpio2":1,
  "gpio3":0
}
```
```json
{
  "id":"node_1",
  "event":"full",
  "ip":"192.168.1.200",
  "name":"새기기",
  "fw":"2.1.0",
  "relay1":1,
  "relay2":0,
  "pc_on":true,
  "gpio1":0,
  "gpio2":1,
  "gpio3":0,
  "uptime":12345,
  "mqtt":true
}
```

### 4.3 Ping (MQTT only)

**Before**: 별도 구조 없음
**After**: topic_ping에 발행
```json
{"id":"node_1","ip":"192.168.1.200","fw":"2.1.0"}
```

### 4.4 Command Reference (API 문서용)

| Command | 설명 | 필수 필드 | 선택 필드 |
|---------|------|-----------|-----------|
| `relay` | 릴레이 제어 | `relay`(1-2), `state`("on"/"off") | - |
| `pulse` | 릴레이 펄스 | `relay`(1-2) | `duration`(ms, 기본 500) |
| `status` | 전체 상태 요청 | - | - |
| `wol` | Wake-on-LAN | - | `mac`(기본: 설정값) |
| `reboot` | 재부팅 | - | - |

### 4.5 Status Event Reference (API 문서용)

| Event | 발생 시점 | 포함 필드 |
|-------|-----------|-----------|
| `online` | 부팅/MQTT 연결 시 | `id`, `ip`, `name`, `fw` |
| `relay` | 릴레이 상태 변경 시 | `id`, `relay1`, `relay2` |
| `pcled` | PC 전원 상태 변경 시 | `id`, `pc_on` |
| `gpio` | GPIO 상태 변경 시 | `id`, `gpio1`, `gpio2`, `gpio3` |
| `full` | status 명령 응답 시 | 모든 필드 |

## 5. Web Request 상세

### 5.1 동작 원리

IO 상태(relay, gpio, pcled) 변경 시 → 설정된 URL로 HTTP GET 호출

```
[IO 상태 변경] → [플레이스홀더 치환] → [HTTP GET 호출] → [응답 무시 (fire-and-forget)]
```

### 5.2 지원 이벤트 및 URL 설정

| 이벤트 | 트리거 | 예시 URL |
|--------|--------|----------|
| relay1_on | 릴레이1 ON 시 | `http://myserver.com/api?device=[device_id]&relay1=on` |
| relay1_off | 릴레이1 OFF 시 | `http://myserver.com/api?device=[device_id]&relay1=off` |
| relay2_on | 릴레이2 ON 시 | (동일 패턴) |
| relay2_off | 릴레이2 OFF 시 | (동일 패턴) |
| pcled_on | PC 전원 켜짐 | `http://myserver.com/api?device=[device_id]&pc=on` |
| pcled_off | PC 전원 꺼짐 | `http://myserver.com/api?device=[device_id]&pc=off` |
| gpio1_high | GPIO1 HIGH | `http://myserver.com/api?device=[device_id]&gpio1=1` |
| gpio1_low | GPIO1 LOW | (동일 패턴) |
| gpio2_high / gpio2_low | GPIO2 변경 | (동일 패턴) |
| gpio3_high / gpio3_low | GPIO3 변경 | (동일 패턴) |

### 5.3 플레이스홀더

| 플레이스홀더 | 치환값 | 예시 |
|-------------|--------|------|
| `[device_id]` | 장치 ID | `node_1` |
| `[device_name]` | 장치 이름 | `새기기` |
| `[ip]` | IP 주소 | `192.168.1.200` |
| `[mac]` | MAC 주소 | `AA:BB:CC:DD:EE:FF` |
| `[event]` | 이벤트 이름 | `relay1_on` |
| `[value]` | 상태 값 (0/1) | `1` |

## 6. Success Criteria

### 6.1 Definition of Done

- [ ] 새 Command/Status JSON 구조로 RS485/MQTT 통신 동작
- [ ] 기존 WebSocket 대시보드 정상 동작 (내부용 buildStatusJson은 별도)
- [ ] Web Request: IO 변경 시 설정된 URL로 HTTP GET 호출 확인
- [ ] Web Request 설정 UI에서 저장/로드 정상 동작
- [ ] 플레이스홀더 치환 정상 동작
- [ ] deviceconfig.json 하위 호환 (web_request 미설정 시 기능 비활성)

### 6.2 Quality Criteria

- [ ] 컴파일 경고 0개
- [ ] HTTP GET 호출이 main loop 블로킹하지 않음
- [ ] SPIFFS 용량 초과하지 않음 (URL 문자열 길이 제한 128자)

## 7. Risks and Mitigation

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| HTTP GET 호출이 loop() 블로킹 | High | High | FreeRTOS task 또는 비동기 HTTP client 사용 |
| URL 문자열이 SPIFFS/메모리 부족 유발 | Medium | Medium | URL 최대 128자 제한, deviceconfig.json 크기 모니터링 |
| 기존 RS485 연동 앱(APITestUtility) 호환 깨짐 | Medium | High | APITestUtility도 함께 수정 (v2.2 호환) |
| Web Request 대상 서버 무응답 시 task 누적 | Medium | Medium | 타임아웃 5초 + fire-and-forget, 동시 호출 1개 제한 |

## 8. Architecture Considerations

### 8.1 Project Level

| Level | Selected |
|-------|:--------:|
| **Starter** (ESP32 펌웨어 + 내장 Web UI) | ✅ |

### 8.2 Key Architectural Decisions

| Decision | Options | Selected | Rationale |
|----------|---------|----------|-----------|
| HTTP Client | ESP-IDF HTTP / Arduino HTTPClient | HTTPClient | Arduino 호환, 비동기 불가하나 FreeRTOS task로 해결 |
| Web Request 실행 | main loop / FreeRTOS task | FreeRTOS task | loop() 블로킹 방지 |
| URL 저장 | deviceconfig.json / 별도 파일 | deviceconfig.json | 설정 일원화, ConfigManager 재사용 |
| 이벤트 구분 | 통합 URL(파라미터 구분) / 개별 URL | 개별 URL | 사용자가 이벤트별 다른 엔드포인트 호출 가능 |
